# MathEval 多类型高性能求值器设计方案

> 版本：v2.1 设计稿（修订：砍除 Integer 双轨、确认 bool 数值语义）
> 日期：2026-08-14
> 状态：待评审
> 前置讨论：string 一等公民 / tagged union / 静态 vs 动态类型 / NFun 对标 / Integer 与 bool 取舍
> 历史参考：commit `058565a^`（string/long/double 三类型 + 插值完整实现）

---

## 1. 背景与演进

### 1.1 项目类型系统演进

| 阶段 | 类型系统 | 结局 |
|---|---|---|
| v0（`058565a^` 之前） | `string / long / double` 三类型 + 插值字符串 | 运行时 `object` 装载，`is` 检查散落，每次运算 PromoteToDouble，类型分发成本高 |
| v1（`058565a`，当前） | 统一 `double`（bool=1.0/0.0） | 数组路径单一化，性能改善；**string 与插值被整体移除** |
| v2（本方案） | `MathValue` tagged union：**4 Kind**（Number/Text/NumberArray/TextArray） | 恢复 string 表达能力，消除 v0 分发开销与 v1 装箱开销；**不恢复 long 独立类型、bool 保持数值语义** |

### 1.2 v1 的两个结构性代价

1. **装箱热路径**：`TypeHelper.EvaluateBinary(object, object)` 每次二元运算 2 次装箱 + 2 次拆箱 + switch 类型匹配，double 主路径为"统一的类型系统"支付了持续的 GC 税。
2. **表达能力锁死**：string 无法进入表达式（Lexer 层直接拒绝），插值功能（完整实现曾存在）被迫外移。

### 1.3 设计原则（讨论结论沉淀）

> **宽边界，窄内核**：类型系统的表达力花在 API 边界（接受全部 13 种基础类型），求值内核只认 4 个规范 Kind。
>
> **值可以多类型，分发只在一处**：运算入口集中做一次 tuple switch，内部分支只走单类型纯计算。
>
> **动态为主，静态可选**：内核运行时标签兜底，上层叠加可选的 Kind 推断 pass 获得 fail-fast 与编译特化能力。
>
> **可逆的克制**：Kind 是 enum，未来加值不动结构——Integer、Bool 的取舍是"现在不做"，不是"永远不做"。

## 2. 目标与非目标

### 2.1 目标

- [G1] string 为一等公民：字面量、拼接、比较、插值、文本数组、索引
- [G2] 数值单轨 Number(double)：bool=1.0/0.0，位运算经内部 long 临时量（2^53 内精确）
- [G3] 两种一维数组：`double[] / string[]`，各自支持广播、聚合、索引
- [G4] 保留并泛化现有优化：常量折叠、索引下推、编译执行（LCG）
- [G5] Number 主路径**零装箱**，快于 v1
- [G6] 渐进迁移：分 5 个阶段落地，每阶段测试全绿可发布
- [G7] `FastEval` 保持 double 专用定位不动

### 2.2 非目标

- [N1] 不支持异构数组（`object[]`）——回到类型分发地狱
- [N2] 不做完整类型推断引擎（TIC）——无函数定义/递归/泛型，推断退化为平凡树遍历
- [N3] 不支持多维数组、结构体、高阶函数——表达式求值器定位，不做迷你语言
- [N4] 不引入 Roslyn / dynamic / DLR
- [N5] decimal 不进内核（金融场景由自定义函数承载）
- [N6] **不做 Integer(long) 独立 Kind**——受益窗口（>2^53 纯整数链）与求值器定位几乎不相交，却是唯一带提升规则的类型；见 ADR-D4
- [N7] **不做 Bool 独立 Kind**——bool 在表达式语言中没有控制流守卫职责，严格化反而迫使各使用点开隐式转换逃生舱；见 ADR-D13

## 3. 核心决策记录（ADR 摘要）

| # | 决策 | 理由 |
|---|---|---|
| D1 | 值表示 = 24 字节 tagged union struct | 消装箱；16 字节重叠布局被 CLR 禁止（引用字段不可与非引用字段重叠，TypeLoadException） |
| D2 | 内核 4 Kind：Number/Text/NumberArray/TextArray | 分支矩阵 16 项可穷举；**全 Kind 互斥、零提升规则**，类型系统退化为纯格子判断 |
| D3 | 数组保持强类型 CLR 数组（`double[]`/`string[]`），不做 `MathValue[]` | 数值数组内存×3 不可接受；广播循环按 Kind 各一份（泛型 helper 消重） |
| D4 | **Integer(long) 不进内核**（v2.0 稿曾规划双轨，现砍除） | double 对 ≤2^53 整数完全精确，Integer 唯一受益是 >2^53 纯整数链（snowflake/哈希场景，与数学求值几乎不相交）；而它是唯一带提升规则的类型，砍掉后提升规则族整体消失，语义矩阵 36→16。位运算只需**内部 long 临时量**（v1 现状），不需要 Kind。可逆：将来加 `MathKind.Integer` 枚举值即可，结构不动。**已知代价（文档明示）**：`ctx.Set("id", 大于2^53的long)` 在边界归一化即丢精度，含"原样返回"场景 |
| D5 | `+` 任一操作数为 Text → 拼接（继承 v0 语义） | 向后兼容历史设计；其余算术运算符对 Text 报错 |
| D6 | 混合 Kind 的 `==`（Number vs Text）→ TypeMismatch | 强类型方向；`1 == "1"` 几乎必是 bug |
| D7 | 数组字面量元素必须同族（Number 或 Text，混写报错） | 穷举可测；异构无运算语义 |
| D8 | Context 继续存 `object`（宽边界），Identifier 求值时归一化为 MathValue | `ExpressionContext` 公共 API 零 breaking |
| D9 | 函数委托签名改为 `MathValue[]`，提供旧 `object[]` 委托适配器 | 自定义函数调用非数值热路径，边界转换可接受；内核彻底无装箱 |
| D10 | Kind 推断为可选 pass（`ExpressionOptions.StrictTypes`），结果按符号版本缓存 | 符号类型可变是现实；纯静态会击穿 AST 缓存 |
| D11 | 插值 AST 段式结构（TextSegment/ExpressionSegment）原样恢复自 `058565a^` | 与值表示层正交，已被验证的设计 |
| D12 | Fast 模块检测到字符串 token 即报错（或显式配置回退主库） | 保护 Fast 的 double VM 定位 |
| D13 | **bool 保持数值语义（1.0/0.0），不做独立 Kind** | bool 在表达式语言中的全部用途是"比较产物 + 逻辑组合 + 条件选择"，三者数值语义都工作良好；严格 bool 会迫使 `sum(mask)`、`(x>0)+(y>0)`、`if(x,...)` 等惯用法全部开隐式转换逃生舱——与 D6 的强类型方向自相矛盾。Excel/MATLAB/R/NumPy/JS/Python 全部数值化 bool。**已知 footgun（文档明示）**：链式比较 `1 < x < 10` 左结合解析为 `(1<x)<10` 恒真——缓解方式是文档说明，不引入 Kind。边界照旧是真 bool：`Set("flag", true)` 入口归一化、`Eval<bool>()` 出口转换。revisit 信号：布尔索引 `arr[mask]`、谓词函数 `filter(arr, pred)` |

## 5. 值表示层：MathValue

### 5.1 定义

```csharp
namespace MathEval.TypeSystem;

public enum MathKind : byte {
    Number = 0,       // double（含 bool：1.0/0.0）
    Text = 1,         // string
    NumberArray = 2,  // double[]
    TextArray = 3,    // string[]
}

public readonly struct MathValue {
    private readonly MathKind _kind;   // 1B + 7B padding
    private readonly double _num;      // Number：值
    private readonly object? _ref;     // Text：string；*Array：对应 CLR 数组

    public MathKind Kind => _kind;

    // 工厂
    public static MathValue Number(double d) => new(MathKind.Number, d, null);
    public static MathValue Text(string s) => new(MathKind.Text, 0, s);
    public static MathValue Array(double[] a) => new(MathKind.NumberArray, 0, a);
    public static MathValue Array(string[] a) => new(MathKind.TextArray, 0, a);

    // 访问器（错误 Kind 直接抛 TypeMismatchException）
    public double AsNumber => _kind == MathKind.Number ? _num : Throw<double>("number");
    public string AsText => _kind == MathKind.Text ? (string)_ref! : Throw<string>("text");
    public double[] AsNumberArray => _kind == MathKind.NumberArray ? (double[])_ref! : Throw<double[]>("number[]");
    public string[] AsTextArray => _kind == MathKind.TextArray ? (string[])_ref! : Throw<string[]>("text[]");

    // 真值（bool 语义的内核形态）：非零且非 NaN
    public bool IsTruthy => _kind == MathKind.Number && !double.IsNaN(_num) && _num != 0;
}
```

### 5.2 布局说明

- **24 字节**（Kind 8 + double 8 + 引用 8，含对齐）。16 字节方案（double 与引用重叠的显式布局）被 CLR 禁止：引用字段不允许与非引用字段重叠，否则 GC 扫描会把 double 位模式误当指针。
- 24 字节 struct 按值传递仍远优于装箱：装箱 = 24~32B 堆分配 + GC 追踪 + 指针间接；struct = 栈上/寄存器传递，零分配。
- 无位模式复用技巧、无提升逻辑——4 Kind 完全互斥，访问器直白。

### 5.3 边界归一化（宽边界）

```csharp
public static MathValue FromObject(object? value) => value switch {
    null          => MathValue.Text(""),           // 沿用 v0 ToString(null)="" 语义
    double d      => MathValue.Number(d),
    float f       => MathValue.Number(f),          // 全部数值类型统一归 double
    long l        => MathValue.Number(l),          // >2^53 精度损失见 ADR-D4 已知代价
    int i         => MathValue.Number(i),
    short s       => MathValue.Number(s),
    sbyte sb      => MathValue.Number(sb),
    byte b        => MathValue.Number(b),
    ushort us     => MathValue.Number(us),
    uint ui       => MathValue.Number(ui),
    ulong ul      => MathValue.Number(ul),
    bool bl       => MathValue.Number(bl ? 1.0 : 0.0),   // bool 数值化（ADR-D13）
    decimal dec   => MathValue.Number((double)dec),      // 有损，文档标注
    string s      => MathValue.Text(s),
    char c        => MathValue.Text(c.ToString()),
    double[] a    => MathValue.Array(a),
    string[] a    => MathValue.Array(a),
    int[] a       => MathValue.Array(Array.ConvertAll(a, x => (double)x)),  // 复制归一
    long[] a      => MathValue.Array(Array.ConvertAll(a, x => (double)x)),
    _ => throw new TypeMismatchException($"不支持的符号类型：{value.GetType().Name}")
};
```

出口转换（`Calculator.ConvertResult<T>`）扩展：`string → string`（恒等）、`Text → double` 尝试不变（保持 v1 兼容）、数组目标类型 `string[]`；`bool` 出口（1.0/0.0 ↔ true/false）现状保留。

## 6. 类型系统与运算语义

### 6.1 数值语义（单轨）

- 全部数值（含 bool、全部整数基础类型）在内核中均为 `double`。
- **位运算**（`& | xor ~ << >> >>>`）：操作数经现有 v1 逻辑内部转 `long` 计算、结果回 `double`——≤2^53 精确，无需 Kind 参与。
- **整除 `//`、`mod`**：double 语义（现状）。
- **无提升规则**：不存在任何 Kind 之间的隐式数值转换（Integer 双轨已砍，见 ADR-D4）。

### 6.2 二元运算语义总表（4×4）

**算术 `+`**

| l \ r | Number | Text | NumberArray | TextArray |
|---|---|---|---|---|
| Number | + | **拼接** | 广播+ | ✗ |
| Text | **拼接** | **拼接** | ✗ | 广播拼接 |
| NumberArray | 广播+ | ✗ | 逐元素+ | ✗ |
| TextArray | ✗ | 广播拼接 | ✗ | 逐元素拼接 |

拼接 = `l.ToText() + r.ToText()`（数值用 v0 的 ToString 规则：NaN→"NaN"、INF→"INF"、G 格式）。
✗ = TypeMismatchException（错误信息带双方 Kind 名）。

**算术 `- * / // % mod ^`**：仅 Number 与 NumberArray（按上表数值子矩阵广播），Text/TextArray 参与即 ✗。

**比较 `== != < <= > >=`**

| 组合 | 语义 |
|---|---|
| Number ⊕ Number | 数值比较，结果 1.0/0.0（含 bool 产物的全部惯用法） |
| Text ⊕ Text | `string.Compare(Ordinal)`；`==`/`!=` 值相等 |
| Text ⊕ Number | **✗ TypeMismatch**（D6） |
| NumberArray ⊕ NumberArray / Number | 逐元素/广播比较 → 1/0 的 NumberArray |
| TextArray ⊕ TextArray / Text | 逐元素/广播 Ordinal 比较 → 1/0 的 NumberArray |
| 跨族数组 | ✗ |

**逻辑 `and or not !`**：仅 Number（IsTruthy：非零且非 NaN），短路求值保持现状。Text 参与即 ✗。

**位运算**：同算术数值子矩阵（内部 long 临时量）。

### 6.3 bool 数值语义确认表（ADR-D13 落地）

| 场景 | 语义 |
|---|---|
| `true` / `false` 字面量 | `Number(1.0)` / `Number(0.0)`（保留字现状不变） |
| 比较运算结果 | `1.0` / `0.0`（数组比较 → 1/0 的 NumberArray） |
| `and or not xor` 真值 | 非零且非 NaN 为真（现状） |
| `sum([1,2,3] > 2)` | 1（掩码计数惯用法，合法且推荐） |
| `(x>0) + (y>0)` | 计数满足条件的个数，合法 |
| `if(x, a, b)` | x 按真值判断（数值条件合法，同 Excel） |
| `true == 1` | `1.0 == 1.0` → 1（接受，数学上无害） |
| `true + 1` | 2（同 Excel/JS/Python） |
| `Text` 参与 `==` | ✗ TypeMismatch（D6，不受 bool 决策影响） |
| `Eval<bool>()` | 1.0/0.0 ↔ true/false（边界转换，现状） |
| 链式比较 `1 < x < 10` | 左结合 `(1<x)<10`，**恒真 footgun**——文档明示不支持链式比较语义（README/语言参考） |

### 6.4 数组字面量 Kind 推断（求值期）

```
[1, 2, 3]        → NumberArray
[1, 2.5]         → NumberArray（无需提升判断，字面量直接求值为 double）
["a", "b"]       → TextArray
["a", 1]         → TypeMismatch（跨族混写）
[1, x]           → x 为 Number 符号 → NumberArray；x 为 Text → ✗
[]               → NumberArray（空数组默认，长度 0）
```

### 6.5 索引 `arr[i]`

- `i` 数值，`ToInteger` 内部转换（沿用现有范围检查与错误信息）
- 结果 Kind = 元素 Kind（NumberArray→Number，TextArray→Text）
- 下推生成的合成索引对标量的静默回退语义不变

### 6.6 聚合 `max/min`

| 输入 | 结果 |
|---|---|
| NumberArray… | Number |
| TextArray… | Text（Ordinal 最大/最小） |
| 跨族混合 | ✗ |

## 7. 词法层

### 7.1 恢复与新增（源：`058565a^` 的 Lexer，按 v1 现有代码风格移植）

- `TokenType.String`：`ScanString()` 完整恢复——单/双引号、转义 `\n \r \t \b \f \0 \\ \' \" \xHH \uHHHH`、未终止报错。代码在历史提交中已验证，直接移植。
- `TokenType.InterpolatedString`：`ScanInterpolatedString()` 恢复——`$'...'` / `$"..."`、`{{ }}` 转义、大括号深度栈、嵌套字符串 `ScanNestedStringContent`。
- `TokenType.Number`：**与 v1 完全一致，零改动**——整数/小数统一为 double 字面量（Integer 双轨已砍，无字面量区分）。

### 7.2 与 ABNF 的对齐

`Docs/matheval-grammar.abnf` 已定义 `STRING` / `INTERPOLATED-STRING` / `ESCAPE`，本方案严格照办；需补充数组字面量与索引的产生式（`"[" ... "]"`、`PRIMARY "[" EXPRESSION "]"`），随实现一并修订文档。

## 8. 语法层与 AST

### 8.1 AST 变更清单

| 节点 | 变更 |
|---|---|
| `ValueExpression` | 不变（装载 `string` / `double`，求值时包 MathValue） |
| `InterpolatedString` | **恢复**（`058565a^`：`List<InterpolationSegment>`） |
| `InterpolationSegment` / `TextSegment` / `ExpressionSegment(formatSpec)` | **恢复**，原样移植 |

### 8.3 插值格式说明符

`{expr:D4}` `{expr:E2}` `{expr:F2}` `{expr:G}` `{expr:X8}`，仅数值；实现即 v0 的 `TypeHelper.Format`（含 D/X 对 double 的整数性校验），移植即可。

## 9. 求值内核

### 9.1 EvaluationVisitor

```csharp
public class EvaluationVisitor(ExpressionContext context) : IExpressionVisitor<MathValue> {
    public MathValue Visit(ValueExpression expr) => MathValue.FromObject(expr.Value);
    // Identifier: _context.TryGetSymbol(object) → FromObject   ← 边界归一化点
    // Binary/Unary: TypeHelper.EvaluateBinary/Unary(MathValue, MathValue)
    // FunctionCall: FunctionCallEvaluator.Evaluate(MathValue[], ...)
    // InterpolatedString: StringBuilder 组装 Text（v0 逻辑移植，产出 MathValue.Text）
    // ArrayLiteral: 先求值全部元素 → 按 §6.4 规则定 Kind → 构造对应 CLR 数组
```

### 9.2 TypeHelper 分发模式（核心）

**一处集中分发，内部分支只算不判**：

```csharp
public static MathValue EvaluateBinary(BinaryExpressionType op, MathValue l, MathValue r) {
    // 快路径前置：Number×Number 主运算（PGO 分支预测收敛点）
    if (l._kind == MathKind.Number && r._kind == MathKind.Number)
        return MathValue.Number(EvaluateNumberOp(op, l._num, r._num));

    return (op, l._kind, r._kind) switch {
        // + 拼接族
        (Plus, Text, _) or (Plus, _, Text) => Concat(l, r),
        (Plus, TextArray, TextArray) or (Plus, TextArray, Text) or (Plus, Text, TextArray) => ConcatBroadcast(l, r),
        // 数组广播：按 Kind 走泛型 helper
        _ when IsNumberArrayOp(l, r) => Broadcast(op, l, r),   // double[] × double/double[]
        _ when IsTextArrayOp(l, r)   => BroadcastText(op, l, r), // string[] × string/string[]
        _ => throw new TypeMismatchException($"运算符 {op} 不支持 {l.Kind} 与 {r.Kind}")
    };
}
```

要点：

1. **Number×Number 前置快路径**——这是 PGO 的收敛点，等效 JS 引擎内联缓存的效果（.NET Tiered PGO 自动完成，无需手写）。
2. **4 Kind 零提升规则**：switch 无任何类型转换 arm，每个 arm 直落单类型计算——这是砍 Integer 带来的直接简化。
3. `EvaluateNumberOp` 内部是纯 double 运算（现有 `EvaluateDivide/Modulo/Power/Shift` 等私有方法平移；位运算内部 long 临时量）。

### 9.3 FunctionCallEvaluator

```csharp
internal static MathValue Evaluate(ExpressionFunction func, MathValue[] args, bool isAggregate) {
    if (isAggregate) return func(Flatten(args));          // 按族展平，跨族 ✗
    var arrayKind = FirstArrayKind(args);
    if (arrayKind is null) return func(args);             // 纯标量：直调
    return arrayKind == MathKind.NumberArray
        ? BroadcastNumeric(func, args)                    // double[] 广播
        : BroadcastText(func, args);                      // string[] 广播：len(s[i]) 逐元素
}
```

- 数值广播：逐元素组参调用，返回 Number → NumberArray。
- TextArray 广播：逐元素 `string` 传给函数，返回数值 → NumberArray（如 `len(["ab","cde"]) → [2,3]`）。

## 10. 优化层

### 10.1 IndexPushdownOptimizer —— 零改动

纯 AST 语法改写（`(a op b)[i] → a[i] op b[i]`），不触碰类型；拼接广播同样满足逐元素律，下推合法。聚合函数跳过逻辑不变。

### 10.2 ConstantFolder

- 现有 `s_pureFunctions`（double→double）保留。
- `ValueExpression` 常量折叠经由新 `EvaluateBinary` 自动获得多类型能力：`"a"+"b"→"ab"`、`[1,2][0]→1` 免费生效。
- 新增 text 纯函数小表：`len(Text)→Number`、`upper/lower/trim(Text)→Text`（若注册为内置）。

### 10.3 CompiledExpression（LCG）

- `CompileNode` 产出 `MathValue` 表达式树；`TypeHelper.EvaluateBinary(MathValue,MathValue)` 作为调用入口编译进去——现有结构平移。
- **Kind 特化**（阶段 4）：Kind 推断结论中"整棵树 Number"的表达式，编译时跳过全部标签检查，直出 double 运算委托 `Func<ExpressionContext, double>`——NFun 静态类型换性能的机制，本架构下免费获得。
- 插值字符串编译：段循环 emit `StringBuilder.Append`，`ExpressionSegment` 处 emit `TypeHelper.Format/ToText` 调用。

## 11. 静态 Kind 推断（可选 pass）

### 11.1 定位

`ExpressionOptions.StrictTypes` 启用时，求值前运行；不启用则完全跳过（零成本）。**动态为主，静态可选**（D10）。

### 11.2 算法（平凡，非 TIC）

自底向上一遍树遍历 `IExpressionVisitor<MathKind?>`：

- 字面量 / 常量折叠结果 → 已知 Kind
- Identifier → 从当前 Context 符号采样 `MathValue.FromObject(v).Kind`（**运行时类型即推断输入**）
- Binary/Unary → 按 §6.2 语义表查表（4×4），无定义组合 → **执行前抛 TypeMismatchException**（带行列号）
- FunctionCall：
  - 强类型注册（`SetFunction<T1,TResult>`）→ 按签名映射 Kind（double→Number，string→Text，double[]→NumberArray…）
  - 弱类型 `ExpressionFunction(MathValue[])` / 聚合 → 返回 `null`（Any），该子树跳过严格检查
- 插值 ExpressionSegment → 递归推断（仅校验，段结果恒 Text）

### 11.3 缓存与失效

- `ExpressionContext` 增加 `SymbolVersion`（每次 `Set/RemoveSymbol` 递增）。
- 推断结果（表达式文本 + SymbolVersion）缓存于 `OptimizedExpressionCache` 旁路；版本不符即重推。
- 死分支全覆盖：推断遍历全树，与短路求值无关——`cond ? 1 : "a"+[1]` 执行前即报错。

### 11.4 为什么不做 NFun 式 TIC

无函数定义、无递归、无泛型、无重载、无提升规则——TIC 难题在本语言一个都不存在。剩余部分就是一遍带 4×4 表的树遍历，预计 ≤300 行。

## 13. FastEval 边界

- Fast（double VM / Bytecode / JIT 路径）**一行不改**。
- `FastScanner` 词汇预检：发现 `'` `"` `$'` `$"` → 抛 `FastEvalException("包含字符串语法，请使用 MathEval 主库")`，或按配置回退 `Expression.Eval`（建议默认抛错，显式优于隐式）。
- 文档明确：Fast = 纯数值极致路径；主库 = 全类型路径。二者共存构成性能分层。
