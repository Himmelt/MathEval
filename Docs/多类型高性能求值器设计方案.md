# MathEval 多类型高性能求值器设计方案

> 版本：v2.0 设计稿
> 日期：2026-08-14
> 状态：待评审
> 前置讨论：string 一等公民 / tagged union / 静态 vs 动态类型 / NFun 对标
> 历史参考：commit `058565a^`（string/long/double 三类型 + 插值完整实现）

---

## 1. 背景与演进

### 1.1 项目类型系统三次演进

| 阶段 | 类型系统 | 结局 |
|---|---|---|
| v0（`058565a^` 之前） | `string / long / double` 三类型 + 插值字符串 | 运行时 `object` 装载，`is` 检查散落，每次运算 PromoteToDouble，类型分发成本高 |
| v1（`058565a`，当前） | 统一 `double`（bool=1.0/0.0） | 数组路径单一化，性能改善；**string 与插值被整体移除**，long 精度丢失（>2^53） |
| v2（本方案） | `MathValue` tagged union：Number/Integer/Text + 三种一维数组 | 恢复全部表达能力，同时消除 v0 的分发开销与 v1 的装箱开销 |

### 1.2 v1 的两个结构性代价

1. **装箱热路径**：`TypeHelper.EvaluateBinary(object, object)` 每次二元运算 2 次装箱 + 2 次拆箱 + switch 类型匹配，double 主路径为"统一的类型系统"支付了持续的 GC 税。
2. **表达能力锁死**：string 无法进入表达式（Lexer 层直接拒绝），long 数值在 2^53 以上丢精度，插值功能（完整实现曾存在）被迫外移。

### 1.3 设计原则（来自讨论的结论沉淀）

> **宽边界，窄内核**：类型系统的表达力花在 API 边界（接受全部 13 种基础类型），求值内核只认 6 个规范 Kind。
>
> **值可以多类型，分发只在一处**：运算入口集中做一次 tuple switch，内部分支只走单类型纯计算。
>
> **动态为主，静态可选**：内核运行时标签兜底，上层叠加可选的 Kind 推断 pass 获得 fail-fast 与编译特化能力。

## 2. 目标与非目标

### 2.1 目标

- [G1] string 为一等公民：字面量、拼接、比较、插值、文本数组、索引
- [G2] 数值双轨：Number(double) 主路径 + Integer(long) 恢复大整数精度
- [G3] 三种一维数组：`double[] / long[] / string[]`，各自支持广播、聚合、索引
- [G4] 保留并泛化现有优化：常量折叠、索引下推、编译执行（LCG）
- [G5] Number 主路径**零装箱**，快于 v1
- [G6] 渐进迁移：分 6 个阶段落地，每阶段测试全绿可发布
- [G7] `MathEval.Fast` 保持 double 专用定位不动

### 2.2 非目标

- [N1] 不支持异构数组（`object[]`）——回到类型分发地狱
- [N2] 不做完整类型推断引擎（TIC）——无函数定义/递归/泛型，推断退化为平凡树遍历
- [N3] 不支持多维数组、结构体、高阶函数——表达式求值器定位，不做迷你语言
- [N4] 不引入 Roslyn / dynamic / DLR——结论见前期讨论
- [N5] decimal 不进内核（16 字节撑爆值表示；金融场景由自定义函数承载）

## 3. 核心决策记录（ADR 摘要）

| # | 决策 | 理由 |
|---|---|---|
| D1 | 值表示 = 24 字节 tagged union struct | 消装箱；16 字节重叠布局被 CLR 禁止（引用字段不可与非引用字段重叠，TypeLoadException） |
| D2 | 内核 6 Kind：Number/Integer/Text + 三数组 | 分支矩阵 36 项可穷举；全部基础类型（169+ 组合）不可测试 |
| D3 | 数组保持强类型 CLR 数组（`double[]` 等），不做 `MathValue[]` | 数值数组内存×3 不可接受；广播循环按 Kind 各一份（泛型 helper 消重） |
| D4 | Integer 复用 double 槽存位模式 | struct 保持 24 字节；`BitConverter.DoubleToInt64Bits` 零成本 |
| D5 | `+` 任一操作数为 Text → 拼接（继承 v0 语义） | 向后兼容历史设计；其余算术运算符对 Text 报错 |
| D6 | 混合 Kind 的 `==`（Number vs Text）→ TypeMismatch | 强类型方向；"1 == 'a'" 几乎必是 bug |
| D7 | 数组字面量元素必须同族（数值族自动提升，Text/数值混写报错） | 穷举可测；异构无运算语义 |
| D8 | Context 继续存 `object`（宽边界），Identifier 求值时归一化为 MathValue | `ExpressionContext` 公共 API 零 breaking |
| D9 | 函数委托签名改为 `MathValue[]`，提供旧 `object[]` 委托适配器 | 自定义函数调用非数值热路径，边界转换可接受；内核彻底无装箱 |
| D10 | Kind 推断为可选 pass（`ExpressionOptions.StrictTypes`），结果按符号版本缓存 | 符号类型可变是现实；纯静态会击穿 AST 缓存 |
| D11 | 插值 AST 段式结构（TextSegment/ExpressionSegment）原样恢复自 `058565a^` | 与值表示层正交，已被验证的设计 |
| D12 | Fast 模块检测到字符串 token 即回退主库 | 保护 Fast 的 double VM 定位 |

## 4. 总体架构

```
┌─────────────────────────────────────────────────────────────────┐
│ API 边界（宽）                                                    │
│  Expression.Eval / Calculator / ExpressionContext.Set(object)    │
│  SetFunction<T1..T8,TResult> / ExpressionFunction(MathValue[])   │

│ 前端                                                             │
│  Lexer：Number/Integer/String/InterpolatedString/标识符/运算符    │

├─────────────────────────────────────────────────────────────────┤
│ 可选静态层                                                        │
│  KindInferencePass（StrictTypes 时）：执行前算出每个节点的 Kind，    │
│  类型冲突 fail-fast；结果缓存（符号版本号失效）                      │
├─────────────────────────────────────────────────────────────────┤

│ 求值内核（窄）                                                     │

│   → tuple switch 一次分发 → 单类型纯计算                            │
│  FunctionCallEvaluator：按 Kind 的广播 / 聚合展平                  │

│ 值表示                                                            │
│  MathValue（24B struct）：Kind 标签 + double 槽 + 引用槽            │
└─────────────────────────────────────────────────────────────────┘
        MathEval.Fast（独立，double-only VM，字符串→回退主库）
```

## 5. 值表示层：MathValue

### 5.1 定义

```csharp
namespace MathEval.TypeSystem;

public enum MathKind : byte {
    Number = 0,       // double
    Integer = 1,      // long（位模式复用 _num 槽）
    Text = 2,         // string
    NumberArray = 3,  // double[]
    IntegerArray = 4, // long[]
    TextArray = 5,    // string[]
}

public readonly struct MathValue {
    private readonly MathKind _kind;   // 1B + 7B padding
    private readonly double _num;      // Number：值；Integer：long 位模式
    private readonly object? _ref;     // Text：string；*Array：对应 CLR 数组

    public MathKind Kind => _kind;

    // 工厂
    public static MathValue Number(double d) => new(MathKind.Number, d, null);
    public static MathValue Integer(long l) => new(MathKind.Integer, BitConverter.Int64BitsToDouble(l), null);
    public static MathValue Text(string s) => new(MathKind.Text, 0, s);
    public static MathValue Array(double[] a) => new(MathKind.NumberArray, 0, a);
    public static MathValue Array(long[] a) => new(MathKind.IntegerArray, 0, a);
    public static MathValue Array(string[] a) => new(MathKind.TextArray, 0, a);

    // 访问器（错误 Kind 直接抛 TypeMismatchException）
    public double AsNumber => _kind == MathKind.Number ? _num : Throw<double>("number");
    public long AsInteger => _kind == MathKind.Integer ? BitConverter.DoubleToInt64Bits(_num) : Throw<long>("integer");
    public string AsText => _kind == MathKind.Text ? (string)_ref! : Throw<string>("text");
    public double[] AsNumberArray => ...;
    public long[] AsIntegerArray => ...;
    public string[] AsTextArray => ...;

    // 数值族统一视图（Integer/Number → double，用于放宽的数值上下文）
    public double ToNumberInclusive() => _kind switch {
        MathKind.Number => _num,
        MathKind.Integer => BitConverter.DoubleToInt64Bits(_num),
        _ => Throw<double>("number|integer")
    };
}
```

### 5.2 布局说明

- **24 字节**（Kind 8 + double 8 + 引用 8，含对齐）。16 字节方案（double 与引用重叠的显式布局）被 CLR 禁止：引用字段不允许与非引用字段重叠，否则 GC 扫描会把 double 位模式误当指针。此为对前期讨论的修正。
- 24 字节 struct 按值传递仍远优于装箱：装箱 = 24~32B 堆分配 + GC 追踪 + 指针间接；struct = 栈上/寄存器传递，零分配。
- `Integer` 存位模式意味着 `_num` 可能是任意 NaN 位样——无妨，它只是普通 double 字段，GC 不关心，运行时按 `_kind` 解释。

### 5.3 边界归一化（宽边界）

```csharp
public static MathValue FromObject(object? value) => value switch {
    null          => MathValue.Text(""),           // 沿用 v0 ToString(null)="" 语义
    double d      => MathValue.Number(d),
    float f       => MathValue.Number(f),
    long l        => MathValue.Integer(l),
    int i         => MathValue.Integer(i),
    short s       => MathValue.Integer(s),
    sbyte sb      => MathValue.Integer(sb),
    byte b        => MathValue.Integer(b),
    ushort us     => MathValue.Integer(us),
    uint ui       => MathValue.Integer(ui),
    ulong ul      => ul <= long.MaxValue ? MathValue.Integer((long)ul) : MathValue.Number(ul),
    bool bl       => MathValue.Integer(bl ? 1 : 0),   // 继承 v1 的 bool 数值化语义
    decimal dec   => MathValue.Number((double)dec),   // 有损，文档标注
    string s      => MathValue.Text(s),
    char c        => MathValue.Text(c.ToString()),
    double[] a    => MathValue.Array(a),
    long[] a      => MathValue.Array(a),
    string[] a    => MathValue.Array(a),
    int[] a       => MathValue.Array(Array.ConvertAll(a, x => (long)x)),  // 复制归一
    _ => throw new TypeMismatchException($"不支持的符号类型：{value.GetType().Name}")
};
```

出口转换（`Calculator.ConvertResult<T>`）扩展：`string → string`（恒等）、`Text → double` 尝试不变（保持 v1 兼容）、数组目标类型 `long[]/string[]`。

## 6. 类型系统与运算语义

### 6.1 数值族提升规则

```
Integer ⊕ Integer   → Integer   （+ - * 位运算；保留精度）
Integer ⊕ Number    → Number    （提升，精度损失静默接受，与 C# 一致）
Number ⊕ Number     → Number
IntegerArray ⊕ 同理（数组与标量、数组与数组同规则提升）
```

### 6.2 二元运算语义总表

**算术 `+`**

| l \ r | Number | Integer | Text | NumberArray | IntegerArray | TextArray |
|---|---|---|---|---|---|---|
| Number | + | 提升+ | **拼接** | 广播+ | 广播+(→NumberArray) | ✗ |
| Integer | 提升+ | +（long） | **拼接** | 广播+(→NumberArray) | 广播+ | ✗ |
| Text | **拼接** | **拼接** | **拼接** | ✗ | ✗ | 广播拼接 |
| NumberArray | 广播+ | 广播+ | ✗ | 逐元素+ | 提升逐元素+ | ✗ |
| IntegerArray | 广播+ | 广播+ | ✗ | 提升逐元素+ | 逐元素+(long) | ✗ |
| TextArray | ✗ | ✗ | 广播拼接 | ✗ | ✗ | 逐元素拼接 |

拼接 = `l.ToText() + r.ToText()`（数值用 v0 的 ToString 规则：NaN→"NaN"、INF→"INF"、G 格式）。
✗ = TypeMismatchException（错误信息带双方 Kind 名）。

**算术 `- * / // % mod ^`**：仅数值族（Number/Integer/数值数组），Text 参与即 ✗。数组按上表的数值子矩阵广播。

**比较 `== != < <= > >=`**

| 组合 | 语义 |
|---|---|
| 数值族 ⊕ 数值族 | 数值比较（提升后），结果 1.0/0.0（v1 兼容） |
| Text ⊕ Text | `string.Compare(Ordinal)`；`==`/`!=` 值相等 |
| Text ⊕ 数值族 | **✗ TypeMismatch**（D6） |
| 数组 ⊕ 同族数组 | 逐元素比较 → 1/0 数组 |
| 数组 ⊕ 标量 | 广播比较 → 1/0 数组 |
| TextArray ⊕ TextArray / Text | 广播 Ordinal 比较 |
| 跨族数组 | ✗ |

**逻辑 `and or not !`**：仅数值族（IsTruthy：非零且非 NaN）。Text 参与即 ✗。短路求值保持现状。

**位运算 `& | xor ~ << >> >>>`**：操作数 ToInteger（数值族），结果 Integer。数组逐元素。

### 6.3 数组字面量 Kind 推断（求值期）

```
[1, 2, 3]        → IntegerArray
[1, 2.5]         → NumberArray（数值族内提升）
["a", "b"]       → TextArray
["a", 1]         → TypeMismatch（跨族混写）
[1, x]           → x 为数值族符号 → 按符号 Kind 提升；x 为 Text → ✗
[]               → NumberArray（空数组默认，长度 0）
```

### 6.4 索引 `arr[i]`

- `i` 数值族，`ToInteger`（沿用现有范围检查与错误信息）
- 结果 Kind = 元素 Kind（NumberArray→Number，TextArray→Text …）
- 下推生成的合成索引对标量的静默回退语义不变

### 6.5 聚合 `max/min`

| 输入 | 结果 |
|---|---|
| NumberArray… | Number |
| IntegerArray… | Integer |
| TextArray… | Text（Ordinal 最大/最小） |
| 数值族混合（IntegerArray + Number 标量…） | 提升为 Number 后聚合 |
| 跨族混合 | ✗ |

## 7. 词法层

### 7.1 恢复与新增（源：`058565a^` 的 Lexer，按 v1 现有代码风格移植）

- `TokenType.String`：`ScanString()` 完整恢复——单/双引号、转义 `\n \r \t \b \f \0 \\ \' \" \xHH \uHHHH`、未终止报错。代码在历史提交中已验证，直接移植。
- `TokenType.InterpolatedString`：`ScanInterpolatedString()` 恢复——`$'...'` / `$"..."`、`{{ }}` 转义、大括号深度栈、嵌套字符串 `ScanNestedStringContent`。
- `TokenType.Number` 细分：**不拆 token**（保持 v1 的单一 Number token），整数/小数区分在 Parser 完成（文本含 `.`/`e/E` 且非 0x/0o/0b 前缀 → Number，否则 Integer）。理由：token 层无需承担，Parser 一次 `text.IndexOf('.')` 判断成本更低且不影响 Lexer 状态机。

### 7.2 与 ABNF 的对齐

`Docs/matheval-grammar.abnf` 已定义 `STRING` / `INTERPOLATED-STRING` / `ESCAPE`，本方案严格照办；需补充数组字面量与索引的产生式（`"[" ... "]"`、`PRIMARY "[" EXPRESSION "]"`），随实现一并修订文档。

## 8. 语法层与 AST

### 8.1 AST 变更清单

| 节点 | 变更 |
|---|---|
| `ValueExpression` | 不变（装载 `string` / `double` / `long`，求值时包 MathValue） |
| `InterpolatedString` | **恢复**（`058565a^`：`List<InterpolationSegment>`） |
| `InterpolationSegment` / `TextSegment` / `ExpressionSegment(formatSpec)` | **恢复**，原样移植 |
| `ArrayLiteralExpression` | 不变（元素求值后由内核定 Kind） |
| `ArrayIndexExpression` | 不变（含 `IsSynthetic` 标记） |
| 其余节点 | 不变 |

### 8.2 Parser 变更

- `ParsePrimary` 恢复两个 case：`TokenType.String → ValueExpression(text)`；`TokenType.InterpolatedString → ParseInterpolatedString(raw)`。
- `ParseInterpolatedString` / `ParseInterpolationExpression` / `FindFormatColon`（跳过字符串内冒号）从 `058565a^` 移植。
- 数值字面量：整数 → `ValueExpression(long)`，小数/进制 → 现有逻辑（`double`）。

### 8.3 插值格式说明符

`{expr:D4}` `{expr:E2}` `{expr:F2}` `{expr:G}` `{expr:X8}`，仅数值族；实现即 v0 的 `TypeHelper.Format`（含 D/X 对 double 的整数性校验），移植即可。

## 9. 求值内核

### 9.1 EvaluationVisitor

```csharp
public class EvaluationVisitor(ExpressionContext context) : IExpressionVisitor<MathValue> {
    public MathValue Visit(ValueExpression expr) => MathValue.FromObject(expr.Value);
    // Identifier: _context.TryGetSymbol(object) → FromObject   ← 边界归一化点
    // Binary/Unary: TypeHelper.EvaluateBinary/Unary(MathValue, MathValue)
    // FunctionCall: FunctionCallEvaluator.Evaluate(MathValue[], ...)
    // InterpolatedString: StringBuilder 组装 Text（v0 逻辑移植，产出 MathValue.Text）
    // ArrayLiteral: 先求值全部元素 → 按 §6.3 规则定 Kind → 构造对应 CLR 数组
    // ArrayIndex: 按 §6.4
}
```

### 9.2 TypeHelper 分发模式（核心）

**一处集中分发，内部分支只算不判**：

```csharp
public static MathValue EvaluateBinary(BinaryExpressionType op, MathValue l, MathValue r) {
    // 快路径前置：Number×Number 主运算（PGO 分支预测收敛点）
    if (l._kind == MathKind.Number && r._kind == MathKind.Number)
        return MathValue.Number(EvaluateNumberOp(op, l._num, r._num));

    return (op, l._kind, r._kind) switch {
        // + 拼接族
        (Plus, Text, _) or (Plus, _, Text) or (Plus, TextArray, TextArray) ... => Concat(l, r),
        // 数值族提升（Integer 参与且非双 Integer）
        ...
        // 数组广播：归一化后进泛型 Broadcast
        _ when IsArrayOp(l, r) => Broadcast(op, l, r),
        _ => throw new TypeMismatchException($"运算符 {op} 不支持 {l.Kind} 与 {r.Kind}")
    };
}
```

要点：

1. **Number×Number 前置快路径**——这是 PGO 的收敛点，等效 JS 引擎内联缓存的效果（.NET Tiered PGO 自动完成，无需手写）。
2. **先归一模式，再算类型**：数组广播走泛型 helper（`Broadcast<T>(T[] a, T b, Func<T,T,T> op)` 三实例化），不写 36 个全组合。
3. `EvaluateNumberOp` 内部是纯 double 运算（现有 `EvaluateDivide/Modulo/Power/Shift` 等私有方法平移，移位/位运算结果包 `Integer`）。

### 9.3 FunctionCallEvaluator

```csharp
internal static MathValue Evaluate(ExpressionFunction func, MathValue[] args, bool isAggregate) {
    if (isAggregate) return func(Flatten(args));          // 按族展平，跨族 ✗
    var arrayKind = FirstArrayKind(args);
    if (arrayKind is null) return func(args);             // 纯标量：直调
    return arrayKind switch {                              // 按 Kind 选广播循环
        MathKind.NumberArray  => BroadcastNumeric(func, args),
        MathKind.IntegerArray => BroadcastInteger(func, args),
        MathKind.TextArray    => BroadcastText(func, args),  // len(s[i]) 逐元素
        _ => ...
    };
}
```

- 数值族广播统一提升为 NumberArray 调用（自定义函数边界本就 `Convert.ChangeType`，语义连续）。
- TextArray 广播把逐元素 `string` 传给函数，返回数值族 → NumberArray。

## 10. 优化层

### 10.1 IndexPushdownOptimizer —— 零改动

纯 AST 语法改写（`(a op b)[i] → a[i] op b[i]`），不触碰类型；拼接广播同样满足逐元素律，下推合法。聚合函数跳过逻辑不变。**唯一要求**：内核保证所有逐元素运算满足交换下推律（§9 语义已保证）。

### 10.2 ConstantFolder

- 现有 `s_pureFunctions`（double→double）保留。
- `ValueExpression` 常量折叠经由新 `EvaluateBinary` 自动获得多类型能力：`"a"+"b"→"ab"`、`1+2→Integer(3)`、`[1,2][0]→1` 免费生效。
- 新增 text 纯函数小表：`len(Text)→Integer`、`upper/lower/trim(Text)→Text`（若注册为内置）。

### 10.3 CompiledExpression（LCG）

- `CompileNode` 产出 `MathValue` 表达式树；`TypeHelper.EvaluateBinary(MathValue,MathValue)` 作为调用入口编译进去——现有结构平移。
- **Kind 特化**（阶段 5）：Kind 推断结论中"整棵树 Number"的表达式，编译时跳过全部标签检查，直出 double 运算委托 `Func<ExpressionContext, double>`——NFun 静态类型换性能的机制，本架构下免费获得。
- 插值字符串编译：段循环 emit `StringBuilder.Append`，`ExpressionSegment` 处 emit `TypeHelper.Format/ToText` 调用。

## 11. 静态 Kind 推断（可选 pass）

### 11.1 定位

`ExpressionOptions.StrictTypes` 启用时，求值前运行；不启用则完全跳过（零成本）。**动态为主，静态可选**（D10）。

### 11.2 算法（平凡，非 TIC）

自底向上一遍树遍历 `IExpressionVisitor<MathKind?>`：

- 字面量 / 常量折叠结果 → 已知 Kind
- Identifier → 从当前 Context 符号采样 `MathValue.FromObject(v).Kind`（**运行时类型即推断输入**）
- Binary/Unary → 按 §6.2 语义表查表，无定义组合 → **执行前抛 TypeMismatchException**（带行列号）
- FunctionCall：
  - 强类型注册（`SetFunction<T1,TResult>`）→ 按签名映射 Kind
  - 弱类型 `ExpressionFunction(MathValue[])` / 聚合 → 返回 `null`（Any），该子树跳过严格检查
- 插值 ExpressionSegment → 递归推断（仅校验，段结果恒 Text）

### 11.3 缓存与失效

- `ExpressionContext` 增加 `SymbolVersion`（每次 `Set/RemoveSymbol` 递增）。
- 推断结果（表达式文本 + SymbolVersion）缓存于 `OptimizedExpressionCache` 旁路；版本不符即重推。
- 死分支全覆盖：推断遍历全树，与短路求值无关——`cond ? 1 : "a"+[1]` 执行前即报错。

### 11.4 为什么不做 NFun 式 TIC

无函数定义、无递归、无泛型、无重载——TIC 四大难题在本语言不存在（详见前期对比讨论）。剩余部分就是一遍带表的树遍历，预计 ≤300 行。

## 12. 上下文与函数系统

### 12.1 ExpressionContext（公共 API 零 breaking，D8）

- 符号存储保持 `object`（`SymbolEntry` 不变），求值期由 `MathValue.FromObject` 归一化。
- `SetFunction` 强类型重载（T1..T8）保留；`FunctionWrapper.Wrap` 内部转换从 `Convert.ChangeType(args[i], typeof(T))` 改为按 Kind 映射：

| 参数类型 T | 接受的 Kind | 转换 |
|---|---|---|
| double | Number | 直取 |
| double | Integer | 隐式提升（数值族内放宽） |
| long | Integer | 直取 |
| long | Number（整值） | 收窄，非整值 ✗ |
| string | Text | 直取；**数值族不隐式转 string**（强类型边界，区别于 v0 的 Convert.ChangeType） |

### 12.2 函数委托签名（D9）

```csharp
public delegate MathValue ExpressionFunction(MathValue[] args);
```

- 新签名内核零装箱。
- 旧 `ExpressionFunction(object[])` 委托：提供 `ExpressionFunctionAdapter` 包装注册（边界处 `To legacy object[]`），标注 `[Obsolete]`，v2.1 移除。
- 聚合/逐元素 `FunctionFlags` 机制不变。

### 12.3 ToText 规则（拼接/插值共用，移植 v0）

```
NaN → "NaN"；+INF/-INF → "INF"/"-INF"；数值 → "G" 格式；Integer → 不带小数点；Text → 原样
```

## 13. MathEval.Fast 边界

- Fast（double VM / Bytecode / JIT 路径）**一行不改**。
- `FastScanner` 词汇预检：发现 `'` `"` `$'` `$"` → 抛 `FastEvalException("包含字符串语法，请使用 MathEval 主库")`，或按配置回退 `Expression.Eval`（建议默认抛错，显式优于隐式）。
- 文档明确：Fast = 纯数值极致路径；主库 = 全类型路径。二者共存构成性能分层。

## 14. 错误处理

| 场景 | 异常 | 时机 |
|---|---|---|
| 未终止字符串 / 非法转义 | ParseException | 词法 |
| 数组字面量跨族混写 | TypeMismatchException | 求值（或 StrictTypes 推断期） |
| Text 参与非拼接算术 | TypeMismatchException | 求值（或推断期） |
| Text 与数值比较 | TypeMismatchException | 同上 |
| 跨族数组运算 | TypeMismatchException | 同上 |
| 函数参数 Kind 不匹配 | FunctionTypeMismatchException | 调用边界 |
| 插值格式符用于非数值 | EvaluateException | 求值 |
| StrictTypes 死分支类型错误 | TypeMismatchException（带行列） | **执行前** |

所有 TypeMismatch 消息携带双方 Kind 名（`运算符 '+' 不支持 Text 与 NumberArray`），保持现有中文异常契约。
